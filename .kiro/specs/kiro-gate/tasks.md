- [x] 1.1 対象の依頼の検出と、本文が渡る形の判定を作る
  - 入力の先頭の空白を除き、`/kiro-*`・`$kiro-*` のコマンド名と記号を取り出す（直後が空白か末尾のときだけ。先頭以外の言及は対象外）
  - ツールごとの手順書の置き場所（Claude Code は `.claude/skills/<名前>/SKILL.md`、Codex は `.agents/skills/<名前>/SKILL.md`）を求める
  - 本文が渡る形（Claude Code の `/`、Codex の `$`）で、セッション開始時の一覧にあるスキルなら真とする判定を作る
  - 単体試験で、検出する例・しない例（`/kiro-spec-init:`、文中の言及）と、`/kiro-specx` が名前として検出されること、本文が渡る形の判定の真偽（Codex の `/`、Claude Code の `$`、一覧に無いスキルは偽）が確かめられる
  - _Requirements: 1.1, 1.2, 1.3, 2.4_
- [x] 1.2 ツール操作の許可と読み取りの判定を作る
  - 未読のとき、Claude Code は手順書の Read とツールを探す操作を通し、Codex は最初のコマンドが読み取りだけのコマンド（cat・head・nl）で引数を作業場所から解いた道筋が手順書と一致するときだけ通す。それ以外は、読むべき手順書の場所と先に読む必要を理由にして拒否する。読み取り済み・対象なしなら通す
  - 読み取りの成功は、手順書の読み取りの操作で、応答に手順書の最初の空でない行が含まれることで判定する（ツールを探す操作は読み取りにしない）
  - 拒否の理由の文言（読むべき手順書の場所と先に読む必要）もこのタスクで作る
  - 単体試験で、拒否の理由に手順書の場所が入ること、通す・拒否する操作の各例（Codex の `ls <手順書>`・`sed -i`・別のリポジトリの同じ道筋の `cat` は拒否）、失敗の応答や探す操作では読んだ扱いにならないことが確かめられる
  - _Requirements: 2.2, 2.3, 2.4, 2.5_
- [x] 1.3 終了の停止と、先に読む指示・終了を止める理由の文言を作る
  - 対象があり未読で、まだ止めておらず、2 回目の終了でもなければ止め、それ以外は通す判定を作る
  - 先に読む指示（追加の文脈）と終了を止める理由の文言に、手順書の場所と先に読む必要を入れる（拒否の理由は 1.2）
  - 単体試験で、1 回目は止め 2 回目は通すこと、文言に手順書の場所が入ることが確かめられる
  - _Requirements: 2.1, 2.6, 2.7_

- [x] 2. フックの入口と状態
- [x] 2.1 状態の置き場所と、セッション開始・入力のフックを作る
  - 状態を OS の一時ディレクトリの下に、リポジトリの根（スクリプトの位置から求め、作業場所は使わない）とセッションを見分ける値から作った名前で置き、一時ファイルに書いて名前を変える。中身はセッション開始時の一覧と今のターンの状態
  - セッション開始時に、そのツールの手順書の置き場所にある `kiro-*` の名前を一覧に書く（Claude Code の要約の後の開始では書き換えない）
  - 入力のフックで、対象が決まり本文が渡る形なら読み取り済みで、そうでなければ未読で今のターンの状態を書き、未読なら先に読む指示を追加の文脈で返す。`/kiro-*` で始まらない入力・手順書が無い入力では今のターンの状態だけを消す（一覧は残す）。次の `/kiro-*` は前のターンを引き継がない
  - 一時ディレクトリと標準入力の試験で、状態がリポジトリの中に作られないこと、別のセッション・別の根の状態を使わないこと、作業場所を変えても同じ根を使うこと、一覧にあるスキルの本文が渡る形では追加の文脈が出ないこと、自然文・手順書の無い入力を挟んでも一覧が残ることが確かめられる
  - _Depends: 1.1, 1.3_
  - _Requirements: 1.4, 1.5, 2.1, 2.4, 3.3, 3.4, 3.5, 3.6, 4.7_
- [x] 2.2 ツール操作の前後と終了のフックを作る
  - ツール操作の前は拒否のときだけ拒否の出力を返し（許可の出力は出さない）、後は読み取りの成功で今のターンを読み取り済みにする。終了のフックは止めるときに止める出力を返して止めた印を付け、通すときは今のターンを消す
  - 判定できない入力・状態の読み書きの失敗・予期しない例外では、理由を標準エラーに日本語で出し、何も出力せず終了 0 にする
  - 標準入力の試験で、入力 → 拒否 → 読み取り → 通過の一連、未読の 1 回目の終了の停止と 2 回目の通過、壊れた JSON で出力なし・終了 0・標準エラーに理由が出ることが確かめられる
  - _Depends: 1.2, 1.3_
  - _Requirements: 2.3, 2.4, 2.6, 2.7, 3.1, 3.2_

  - 運用の区画の kiro-gate の文章に、要件の対応表、表に該当する依頼は `/kiro-*` で始まらなくても手順書を読んで最後まで実行すること、ツールごとの手順書の読み方、判断できないときは尋ねること、`/kiro-*`（Codex は `$kiro-*`）では読むまで他の作業ツールが拒否されることを入れ、Codex の文章にだけ、フックが未承認でも作業前に手順書を読むことを入れる
  - カタログの試験で、両ツールの 5 つのフック、対応表の行が要件と同じであること、Codex だけの一文が確かめられ、試験一式が通る

## Implementation Notes
- 2.1: 権限を外す試験は、後片付け（一時ディレクトリの削除）より前に権限を戻す（t.after の順序では EACCES になる）。
- 2.2: レビューで 3 回差し戻し（試験の準備の順序・判定できない入力と状態で止める・試験の期待値）。3 回目は試験の 1 行の期待値だけでレビューが直し方まで示したため、原因調査を省いて親が直した。一覧にあるスキルは本文が渡る形で読み取り済みになるので、拒否・停止の試験では手順書をセッション開始の後に作る。
- 3.2: Codex は追加の文脈に必ず従って先に手順書を読むため、自然な実行では拒否・終了の停止が起きない。PoC では Codex の場面だけ、包みで追加の文脈を外して配置した kiro-gate の拒否・停止を確かめた（`poc/kiro-gate/result.md`）。レビューで 1 回差し戻し（読み取りの判定の中身の照合、実行の異常の判定、2 回の入力の期限）。
