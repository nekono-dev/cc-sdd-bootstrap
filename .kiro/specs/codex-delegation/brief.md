# Brief: codex-delegation

## Problem
Codex（OpenAI のコーディングエージェント）が使える環境では、実装やレビューを Codex に任せると、Claude の指揮役のコストを抑えつつ、独立した目でのレビューが得られる。skyshare ではこの仕組みを作り込んだが、skyshare 固有のスクリプトと CLAUDE.md の長い文章に埋まっている。

## Current State
skyshare に、Codex を MCP サーバー（外部ツールを Claude Code へつなぐ仕組み）として提供するスクリプト一式（`codex-mcp-server.mjs` ほか）、Codex が信頼していないリポジトリで入力を止めるフック（`codex-trust-gate.mjs`）、`.mcp.json`、`.codex/config.toml`、CLAUDE.md の委任の決まり（モデルの選び方、失敗時の CLI への切り替え、Codex が使えないときの Claude サブエージェント）がある。

## Desired Outcome
- 導入時に「Codex MCP サーバーを使うか」を選べる。使わない場合は何も配置しない。
- 使う場合、役割（subagent-model-policy の一覧）ごとに Codex の sandbox・モデル・effort を設定でき、Codex が使えないときは同じ役割の Claude エージェント定義に切り替わる。
- Codex のモデル名（今の `gpt-6.1-sol`・`gpt-6-luna`）は設定ファイルで変えられる。

## Approach
skyshare の Codex 関連をクラウド MCP の接続先の一つとして移す。各 MCP の公開情報を読み取る処理を用意し、共通の役割と設定に基づいて委任先を選ぶ。各クライアントからの呼び出し方法は管理区画で案内する。

## Scope
- **In**: MCP サーバーのスクリプト一式、信頼の確認のフック、`.mcp.json` の統合、役割と Codex の割り当ての設定、管理区画の委任の文章。
- **Out**: Codex 本体の導入・認証。

## ハーネス MCP の優先順位（2026-11-20 の合意）

- 委任先は、ローカル型のエージェント MCP、異なる系統のクラウド型エージェント MCP、現在のクライアントのネイティブサブエージェントの順とする。クラウド段では現在のクライアントと同じ系統を除外する。Claude Code、Codex、Pi、Muse など、指揮役の種類に依存しない規則にする。
- セットアップはクライアントに登録済みの MCP を機械的に列挙する。対応するエージェント型 MCP の中から利用者が候補と各段の優先順を設定する。新規登録した MCP もこの手順で候補に加える。独立した CLI は必須としない。
- cc-sdd がサブエージェントを必要とするたびに、承認済みの候補から受付モデル ID と機能を取り直し、役割ごとの適格条件で委任先を決める。受付モデル一覧の管理は MCP 側の責務とする。委任側はバックエンドを照会しない。自動選択は候補を更新し、明示固定した値は保持する。
- 起動前に利用不可と確認できれば次の候補へ進む。起動後に状態が不明な場合は状態を確認し、同じ書き込み作業を並行して開始しない。

## ローカル MCP の技術要件

- 対応するプロトコルでエージェント型であること、ハーネスの種類、受付モデル ID を機械可読に公開する。作業ディレクトリを指定してジョブを開始し、開始済みのジョブを識別して状態取得・停止できる。単純応答型と種別を判定できない MCP は利用対象から外す。
- 役割に必要な実行権限をサーバー側で強制し、対応権限を機械可読に公開する。読み取り専用では編集・書き込み・シェルをエージェントに提供せず、作業先の書き込みを実行環境でも禁止する。製造では指定した作業ディレクトリで編集とテスト実行を許可する。対応しない権限は起動前に拒否する。
- 指定された推論量を適用できるか、起動前に機械判定できるようにする。要求された推論量に対応しない場合は、別の推論量へ黙って落とさず、その役割で次の候補を選ぶ。推論量の条件は subagent-model-policy が定める。
- 既設の Pi MCP では、`initialize` のサーバー名と `tools/list` の起動・状態確認・停止のスキーマを照合できる。受付モデル ID は `pi_models` の構造化結果から取得する。実機の `pi_capabilities` はハーネスの種類、ローカル実行、対応する権限と推論量を返す。現行構成が公開する推論量は `off` のみなので、`medium` / `high` が必要な依頼は次の候補へ進む。プロトコル名とフィールドは、他のハーネスにも同じ名前を要求せず、対応する契約を確認して取り込む。

## Boundary Candidates
- MCP サーバー（実行・列・権限）
- 信頼の確認
- セットアップでの MCP の探査と優先順の設定、委任直前の候補の確認と選択

## Out of Boundary
- Claude サブエージェントのモデルの判定（subagent-model-policy）

## Upstream / Downstream
- **Upstream**: installer-core、subagent-model-policy（役割の一覧）
- **Downstream**: なし

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: subagent-model-policy

## Constraints
- 要件の段階で決めること: `.codex/config.toml` を配置するか、skyshare 固有の検証の分担（`test:imports` など）を外した汎用の委任の文章の範囲。
- PoC: MCP サーバーが `codex` の無い環境でツールを出さずに起動すること、`.mcp.json` の承認（settings.local.json）の扱い。
