## Implementation Notes

- 上流の役割契約と起動ガードの実装・実機検証を先に完了する。この計画の承認は上流を実装済みと扱う根拠にはしない。
- 3.2 と 3.3 は同じ公開サーバーを変更するため順に実施する。登録と配布の計画・配置記録の変更は上流との統合順を守る。
- 現行の Pi MCP が公開する推論量は `off` のみ。役割選択の正常系は対応を公開するテスト用サーバーで確認し、実機では非該当の除外と、明示的な接続契約の検証を行う。
- 1.1 は上流の実装ゲート GO を確認した。登録済み Pi の能力と受付モデル、Codex のモデルカタログを機械的に照合し、両クライアントの一時検証で利用者専用領域への書き込みは拒否された。現行 Pi の推論量は off のみなので役割候補に使わない。
- 1.2 は delegation[host] の local・cloud を別々の順序付き配列とした。候補は family・scope・registrationName・registrationId と models を持ち、役割別モデルは fixed または compatibleIds を使う。未指定・空順序・旧設定・明示モデルの保持と不正値の適用前拒否を確認した。
- 3.3 の Codex ジョブは、停止要求後はプロセスグループの消滅を確認してから停止済みを返す。停止要求の前に本体が終了し子孫だけが残るケースの追跡は 3.3 の範囲外とし、必要なら 6.2 の障害時の通しで扱う（レビューで残った制限）。
- 4.1 の候補選択は入力（settings）の内部の役割キーの綴り検査をしない。設定の形の検査は 1.2 の設定の検証が適用前に行う。
