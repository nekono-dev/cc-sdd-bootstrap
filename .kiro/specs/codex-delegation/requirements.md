# Requirements Document

## Project Description (Input)
cc-sdd の利用者は、指揮役のクライアントや導入済みの MCP が異なる環境で、製造・レビュー・設計をエージェントに委任する。現状は、このリポジトリや skyshare の個別の指示と Codex 向けの構成に選択が依存する。セットアップで登録済みのエージェント型 MCP を見つけ、候補と優先順を設定する。各委任の直前にモデル ID と機能を確認し、異なる系統のクラウド型 MCP、ネイティブサブエージェントの順に、役割に適合する候補を選ぶ。ローカルで実行されるエージェント（Pi など、利用者の端末やその近くのモデルを使う MCP）は委任先に使わない。

## Introduction

cc-sdd の利用者が、現在のクライアントにかかわらず、登録済みのクラウド型エージェントの中から役割に合う委任先を使えるようにする。設定時に候補と優先順を選び、委任直前に最新の公開情報で利用可否を確認する。適格な候補がなければ、現在のクライアントのネイティブサブエージェント（クライアント自身が持つ子のエージェント）に任せる。

> 改訂（2026-11-22）: ローカル型のエージェント MCP を委任先から外した。実機でローカルのモデルが実用に足りなかったため（`poc/codex-delegation-live/result.md`、`research.md` の「ローカル除外の決定」）。旧 2.5 を削除し、要件 4 を「対応するエージェント MCP の技術要件」に一般化した。番号は詰めていない（旧 2.5 は欠番）。対応は `design.md` の「変更の影響」を参照する。

> 改訂（2026-11-22、推奨案の採用）: 要件 3.6〜3.8 を追加した。cc-sdd の作業中は、委任先に選ばないもの（Pi など）を含め、既知のエージェント MCP の起動ツールの直接起動を拒否する。Pi を拒否の対象から外すと、Pi が登録済みの環境で、管理入口・役割別のモデル指定・書き込みの二重起動の防止・依頼の追跡をすべて迂回して起動できてしまうため。理由は `research.md` の「推奨案の採用（2026-11-22）」を参照する。

## Boundary Context

- **対象** — セットアップにおける登録済み MCP の探査、候補と順序の設定、実行時の選択と切り替え、委任先として対応するエージェント MCP の適格条件、cc-sdd の作業中のエージェント MCP の直接起動の拒否（委任先に選ばない MCP を含む）。
- **対象外** — ハーネス本体とモデルの導入・認証、MCP の背後にあるモデル提供先の直接確認、cc-sdd 本体の改変、特定プロジェクト専用の試験手順、ローカル実行のエージェント MCP（Pi など）への委任（委任はしないが、作業中の直接起動は要件 3.6 で拒否する）。
- **隣接仕様** — installer-core は導入・更新の入口と設定の保存を提供する。subagent-model-policy は役割・モデル・推論量・権限の条件と、ネイティブ起動の方針を定める。管理入口への呼び出し参照の付け足しと、ネイティブ単独の事前確認の可否の判定も同仕様が定める（同仕様の要件 5・6）。既存の Codex MCP の利用選択と導入対象クライアントの選択は独立して扱う。

## Requirements

### Requirement 1: セットアップでの探査と優先順の設定

**目的** — 利用者が設定画面やファイルを一つずつ探さずに、登録済み MCP の中から委任先を選択できるようにする。

#### Acceptance Criteria

1. When 利用者が cc-sdd-bootstrap の導入または更新を行うとき, the 委任機能 shall その作業の中で委任をセットアップできるようにする。
2. When 利用者が委任をセットアップするとき, the 委任機能 shall 対象クライアントに登録済みの MCP を機械的に列挙する。
3. When 登録先がクラウド型のエージェント型 MCP と確認できるとき, the 委任機能 shall サーバーの識別名、ハーネスの系統、クラウド型であることを利用者に示す。
4. If MCP が単純応答型か、エージェント型・ハーネスの系統を確認できないか、公開された実行形態からクラウド型と確認できない（ローカル型と確認できるものを含む）とき, then the 委任機能 shall その MCP を委任候補から外す。
5. When 利用者が委任候補を選ぶとき, the 委任機能 shall クラウド型の候補について先に試す順を指定し、保存できるようにする。
6. If 利用者が登録済みの MCP をセットアップで選択していないとき, then the 委任機能 shall その MCP に委任しない。
7. When 利用者が委任設定の変更を指定せずに更新するとき, the 委任機能 shall 既存の利用選択と候補順を引き継ぐ。

### Requirement 2: 委任直前の確認とモデルの見直し

**目的** — 利用者が候補のモデルが変わるたびに設定を書き直さず、明示的な固定指定も維持できるようにする。

#### Acceptance Criteria

1. When cc-sdd がサブエージェントへの委任を必要とするとき, the 委任機能 shall 選択対象となる承認済み MCP の受付モデル ID と関連する実行機能を起動前に機械的に確認する。
2. The 委任機能 shall MCP が公開する受付モデル ID をモデル候補の根拠とする。
3. When 自動選択中のモデル候補が変わったとき, the 委任機能 shall 最新の公開一覧から役割条件に適合するモデルをその委任で選ぶ。
4. If 利用者が明示固定した MCP のモデル ID が公開一覧にないか、役割条件を満たさないとき, then the 委任機能 shall 固定値を保持し、その候補を外して次の候補を確認する。

### Requirement 3: 実行先の固定優先順

**目的** — 指揮役のクライアントを変更しても、利用可能な候補を同じ原則で使えるようにする。

#### Acceptance Criteria

1. The 委任機能 shall クラウド型エージェント MCP（現在のクライアントと同じ系統を除く）、現在のクライアントのネイティブサブエージェントの順で、役割条件に適合する候補を選ぶ。
2. When 同じ段に複数の適格候補があるとき, the 委任機能 shall セットアップで利用者が保存した順に候補を選ぶ。
3. If クラウド型 MCP のハーネスが指揮役を実行しているクライアントと同じ系統のとき, then the 委任機能 shall その MCP を候補から外す。
4. When Codex MCP がクラウド段の承認済み候補で、指揮役のクライアントが Codex 系統以外であるとき, the 委任機能 shall 他のクラウド型 MCP と同じ適格条件と設定順を適用する。
5. If 適格な MCP 候補がなくネイティブでの起動もできないとき, then the 委任機能 shall 起動を行わず、利用者に委任先を選べなかった理由を示す。
6. While cc-sdd の作業中, the 委任機能 shall 既知のエージェント MCP の起動ツールを、管理された委任入口を通さずに直接呼ぶことを拒否する。対象には、委任先に選ばないエージェント MCP（Pi などのローカル型）の起動ツールを含める。
7. When 要件 3.6 により直接起動を拒否したとき, the 委任機能 shall 管理された委任入口を使うよう理由で示し、入口が選ぶのはクラウド型エージェント MCP またはネイティブサブエージェントであることを伝える。
8. The 委任機能 shall cc-sdd の作業外のエージェント MCP の呼び出しには要件 3.6 の拒否を適用しない。

### Requirement 4: 対応するエージェント MCP の技術要件

**目的** — 委任した処理を実行・追跡でき、役割に必要な権限と推論量を守れるようにする。本仕様が配布する Codex MCP はこの要件を満たす対象とする。

#### Acceptance Criteria

1. The 対応エージェント MCP shall エージェント型であること、ハーネスの系統、実行形態（クラウド型であること）、受付モデル ID、対応する権限と推論量を機械可読に公開する。
2. When 対応するモデル・権限・推論量で作業先を指定した依頼を受け付けたとき, the 対応エージェント MCP shall 作業を開始し、状態確認と停止に使えるジョブ識別子を返す。
3. When 読み取り専用の依頼を実行するとき, the 対応エージェント MCP shall 編集・書き込み・シェルによる作業先の変更をエージェントに許さず、作業先への書き込みを実行環境でも禁止する。
4. When 製造のために書き込み許可を指定した依頼を実行するとき, the 対応エージェント MCP shall 指定された作業先での編集とテスト実行を許可する。
5. If 要求されたモデル・権限・推論量の組み合わせに対応しないとき, then the 対応エージェント MCP shall 別のモデルや権限、推論量で起動せず、理由を返す。
6. When 利用者がジョブ識別子を使って状態の取得または停止を求めたとき, the 対応エージェント MCP shall 対象のジョブの状態または停止結果を返す。

### Requirement 5: 起動前後の失敗と切り替え

**目的** — 一時的に使えない委任先から回復し、同じ作業への二重実行を防げるようにする。

#### Acceptance Criteria

1. If 選んだ MCP が起動前に利用できないと確認したとき, then the 委任機能 shall 失敗した候補を外し、設定済みの順で次の適格候補を確認する。
2. If 起動要求の後で作業が開始済みか、または継続中か判断できないとき, then the 委任機能 shall 切り替えの前に先行ジョブの状態を確認する。
3. While 先行ジョブの停止または終了が確認できず、同じ書き込み作業を引き継ぐとき, the 委任機能 shall 別の委任先を起動せず、確認できない状態を利用者に示す。
