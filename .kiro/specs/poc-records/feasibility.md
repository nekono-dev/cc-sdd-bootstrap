# 実現性の記録: poc-records

## 実機検証の要否
- 判定: 必要
- 理由: 中心の変更は文章・テスト・文書の書き換えだが、次の前提が Claude Code・Codex の動作に依存する。Codex の `workspace-write` ではリポジトリの外へ書けないことは、設計前の実機検証（2026-11-25、Codex CLI 0.172.0、`-s workspace-write`）で確認済みであり、「PoC のスクリプトをリポジトリの管理対象の外で動かす」ことが両ツールで成り立つかを実機で確かめる必要がある。前提ごとの PoC は、この spec の設計の段階で `poc/design_<通し番号>.md`（新方式）として残す。
  - (a) 両ツールの指揮役が、リポジトリの管理対象の外のディレクトリでスクリプトを作って実行し、リポジトリの `git status` を変えずに結果を得られるか（Claude Code の許可・Codex の `workspace-write`）。
  - (b) 運用の区画の文章に従った PoC の流れ（実行 → PoC 文書だけを spec のディレクトリに書く）が、両ツールで実際に成り立つか。
- PoC を作らない前提: なし（現時点）。
