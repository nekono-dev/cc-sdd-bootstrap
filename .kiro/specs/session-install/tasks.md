# Implementation Plan

> 改訂（2026-11-23）: 単純化後の設計に合わせて作り直した。旧版のタスク（SessionStart での導入・内容の照合・雛形の保持・別スクリプトの停止）は git の履歴にある。カタログの登録（4.1）は、installer-core がカタログを新しい形に切り替えた後（installer-core 5.1）に行う。

- [ ] 1. 判断の規則（純粋）
- [x] 1.1 設定の読み取りと状態の記録を新しい形にする
  - 設定の項目定義から雛形の保持の項目を外し、読み取りは installer-core と同じ扱い（必須は `format` だけ、値のある項目は検証、無い項目は既定値）にする
  - 状態の記録を、版・言語と、導入に成功したときの導入物の相対の道筋の一覧（中身は持たない）の形にし、旧版の形（指紋つき）は読めない扱いにする
  - 単体試験で、設定が無い・読めない・不正のときに設定ファイル名と直し方つきの誤りになること、新しい状態の記録の読み書きと旧版の記録が読めない扱いになることが確かめられる
  - _Requirements: 3.4, 4.4_
- [x] 1.2 入れ直しの判断を作り直す
  - 判断の材料を、設定・状態・導入中の印（新しさ）・失敗の記録・記録した道筋のうち今は無いもの・両文書の運用の区画の有無にする（内容の照合をしない）
  - 設定の誤りは失敗、導入中の印があれば導入しない（新しい・古いの別を返す）、失敗の記録があれば入れ直し、版・言語の不一致・状態なし・記録した道筋の欠け・区画なしで入れ直し、すべて揃えば省く
  - 単体試験で、上の各場合の判断と、内容だけが変わった導入物では省くことが確かめられる
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 5.5_
- [ ] 1.3 導入の計画（消す対象・manifest・npx の引数）を両ツール向けにする
  - 消す対象を、両ツールのスキルのうち `kiro-` で始まるものと `.kiro/settings` に限る（独自のスキル・仕様・方針・`.codex/agents` を含めない）
  - manifest をツールごとに、スキル・標準の文書（Claude Code は CLAUDE.md、Codex は AGENTS.md をリポジトリの直下へ）・設定の雛形にし、Codex の既定のエージェント定義を含めない
  - npx の引数をツールごとに組み立てる（版・言語・manifest・強制上書き）
  - 単体試験で、消す対象の範囲、両ツールの manifest の出力先と中身、引数が確かめられる
  - _Requirements: 3.1, 3.2, 3.3, 3.7_
- [ ] 1.4 文言を新しい流れに合わせる
  - 導入した・省いた（版・言語つき）、手順書を直接読む（ツールごとの手順書の置き場所。`/kiro-x`・`$kiro-x` で始まる入力ならその手順書を名指し）、止めた理由（失敗の詳細、詳細が無いときは完了を確認できない旨、導入中・中断の別と、中断なら印を消して再試行する 1 行）、利用手順（準備スクリプトの 1 行・手元の初回の始め方・未導入の `/kiro-*` が拒否されたときの準備し直し方）を作る
  - 単体試験で、それぞれの文言に必要な項目が入ることが確かめられる
  - _Requirements: 1.1, 2.3, 2.4, 2.5, 5.3, 6.1_

- [ ] 2. 導入の実行と CLI
- [ ] 2.1 判断の材料を読む処理と試験の土台を作る
  - 設定・状態の記録・導入中の印の有無と経過時間・失敗の記録・記録した道筋のうち今は無いもの・CLAUDE.md と AGENTS.md の運用の区画の有無を読み、判断（1.2）の材料にまとめる処理を作る。旧版の指紋の収集を外す。CLI と 2 つのフックはこの 1 か所の読み取りを使う
  - 試験の土台（偽の npx と一時ディレクトリの用意）を、両ツールの導入物と新しい標準の文書の出力先（リポジトリの直下）に対応させ、installer-core の運用の区画のファイルを置けるようにする
  - 一時ディレクトリの試験で、各材料（古い印・新しい印・失敗の記録・欠けた道筋・区画の無い文書）が正しく読まれることが確かめられる
  - _Depends: 1.1, 1.2_
  - _Requirements: 4.1, 4.2, 4.3, 5.5_
- [ ] 2.2 導入の実行を作り直す
  - 導入中の印を排他的に作り（作れなければ導入しない。自動の回収はしない）、消す対象を消し（シンボリックリンクの経路は失敗）、Claude Code 向け → Codex 向けの順に npx を実行する。2 回を合わせた導入全体の期限で打ち切り、npx の出力はフックの出力を汚さないよう標準エラーへ流す
  - installer-core が配置した運用の区画のファイルを、CLAUDE.md・AGENTS.md の末尾に書き足す（ファイルが無い・書けないなら失敗）
  - 導入物の道筋を集めて状態を書き、失敗の記録を消し、最後に印を消す。途中の失敗は失敗の記録に理由を書いて印を消す
  - 2.1 の土台を使った試験で、両ツールの導入物と末尾に区画が 1 つある両文書ができること、2 回目に入れ直すと区画が重ならないこと、既存の CLAUDE.md の記述が消え独自のスキル・仕様が残ること、npx の失敗・期限切れ・区画のファイルが無いときに失敗の記録が残り印が消えることが確かめられる
  - _Depends: 1.3_
  - _Requirements: 1.2, 3.1, 3.2, 3.3, 3.8, 3.9, 5.1, 5.4, 5.5_
- [ ] 2.3 起動前・再試行の CLI を整える
  - 引数なしで判断して導入または省き、結果と版・言語を表示する。失敗・設定の誤り・導入中の印では理由と再試行の方法を表示して終了コード 1 にする。対話はしない
  - `--help` で利用手順を表示する。SessionStart での導入の動作と旧版の引数を外す
  - 一時ディレクトリの試験で、成功で終了 0、失敗で終了 1 と理由、導入中の印があると導入せず終了 1、`--help` の表示が確かめられる
  - _Depends: 1.4_
  - _Requirements: 1.1, 1.2, 1.4, 2.4, 2.5, 3.6_

- [ ] 3. フック（同じスクリプトの中にあるため順に行う）
- [ ] 3.1 セッション開始時に状態を知らせる
  - 判断だけを行い導入はせず、省く場合は揃っている旨と版・言語、それ以外は最初の入力で導入する・入力が止まる旨を、セッション開始の追加の文脈として返す。誤りでは何もせず終了 0
  - 標準入力の JSON を渡す試験で、両ツールの指定で知らせの文言が返り、導入が始まらないことが確かめられる
  - _Depends: 1.4, 2.1_
  - _Requirements: 3.6_
- [ ] 3.2 最初の入力で導入し、未完了なら止める
  - 判断が「省く」なら何も出さない。「入れ直し」なら導入を実行し、成功なら導入した旨と手順書を直接読む旨を追加の文脈で返し、失敗なら止める。導入中の印・設定の誤り・判定中の例外でも止め、理由と再試行の方法を示す
  - 偽の npx を使った試験で、未導入の最初の入力で導入と追加の文脈が返ること、失敗後の入力が止まり再試行の成功で止まらなくなること、壊れた設定で止まること、2 つの入力をほぼ同時に送っても npx を呼ぶのは 1 つで他方は止まること、印が残ったときは止まり印を消す 1 行が示されることが確かめられる
  - _Depends: 2.2_
  - _Requirements: 2.1, 2.2, 2.3, 5.2, 5.5, 5.6_

- [ ] 4. カタログへの登録と実機の確認
- [ ] 4.1 カタログに session-install の項目を登録する（統合）
  - 新しい形のカタログに、2 つのスクリプト、両ツールの SessionStart と UserPromptSubmit のフック（入力のフックは kiro-gate の項目より前、時間切れは導入全体の期限より長く）、運用の区画の session-install の文章（導入の時点と省略、`kiro-` で始まる独自のスキルを置かない、未完了の停止と再試行、手順書を直接読む方法と見つからないときは進めない、独自の決まりは steering から読む。Codex の文章にだけ、フックが未承認なら作業前に導入を実行・確認して失敗なら止める指示と、停止が機械的には保証されない旨）を登録する。旧版の入力の停止のスクリプトとその試験を消し、配る範囲とカタログから外す（新しいフックへの登録の切り替えと同時に行う）
  - カタログの試験で、両ツールの 4 つのフック、区画の文章の各要素、Codex だけの文章、除外の行に導入物と記録の置き場所が含まれることが確かめられ、試験一式が通る
  - _Depends: installer-core 5.1_
  - _Requirements: 3.5, 6.2, 6.3, 6.4, 6.5_
- [ ] 4.2 実機で導入と停止を確かめる

  - 導入の PoC（`poc/self-install/run.sh`）を、一時のリポジトリに新しい配置物とフックの登録を置き、Codex も含めて確かめる形に更新して実行する。起動前に導入した最初のセッションでスキルが一覧に載り、最初の入力時の導入と停止が両ツールで働くことを記録する（このリポジトリ自身での確認は installer-core 7.2）
  - _Requirements: 1.3, 2.1, 2.2_

## Implementation Notes
- 1.1: Codex の利用上限の間、実装は Claude Code のサブエージェント（Haiku）、レビューは Sonnet で行った。install-cc-sdd.mjs は試験を通す最小限の付け替え（雛形の保持を false に固定、指紋をやめて道筋の有無で判断）にとどめ、2.x で組み直す。decideInstall の理由名は files-missing を足し templates-missing を消した（1.2 で引き継ぐか確かめる）。読み取りは configFields の全項目を検証する（codex.enabled・models も。subagent-delegation 1.1 で項目定義が変わる）。
- 1.2: install-cc-sdd.mjs の判断の呼び出しは仮置き（導入中の印は常に無し、区画は常に有り）。CLI の分岐は fail・busy を区別せず導入に進むので、2.1 で材料を読むときに直す。
