## Implementation Notes
- 1.1: `maxModel` は系統の語との完全一致だけを受け付ける（版付きの名前・設定の `tiers` で足した語は誤り）。設定で足した系統の明示モデルは、役割表の `provider` から決まる委任先の提供元の上限と比べる。レビュー役（`codex exec --sandbox read-only`）の環境では既存の試験が一時ディレクトリの作成で失敗する（EROFS）ので、親が実行した `npm test` の結果と、実装役の報告の RED の出力をレビューの依頼に添える。
- 1.2: `ConfigField` の `flag`・`question` は任意にした（lib/ は参照しない）。`subagentsField.kind` は JSDoc の型検査で `string` と推論され `ConfigField[]` への代入で型の不一致が残る（実行時の影響なし。触るときに `"map"` のリテラル型で注釈する）。配布物の起動の試験は `npm pack` の成果物を展開して `help` を実行する。
- 2.1: 推論量は `resolveEffort(explicitEffort, childModel, cfg)` → `{effort, notices}` で、確定した子のモデルから求め直す（2.3・3.2 はこれを使う）。`resolveRole(cfg, from, role, orchestratorModel, opts)` は `{ok:true, target, setting, selfImplement, effort, definitionName, notices}` か `{ok:false, reason}`。`setting.effort` は役割設定の元の値、実際の推論量は `effort`。`opts.to` は `"same"`・`"other"`。明示のモデルを置き換えるのは `to:"same"` で提供元が食い違うときだけ（知らせを返す）。`to:"other"` で食い違えば置き換えず理由を返す。`definitionName` は Claude の生成対象の系統のときだけ（対象外は null と知らせ）、Codex は書き込み可の役割だけ `cc_sdd_<役割>`。同じ提供元で候補が無ければ `selfImplement:true`（`defaultModelFor` は `{kind:"self"}`）。
- 2.2: `decideSpawn({vendor, childModel, childEffort, orchestratorModel}, cfg)` の `vendor` は指揮役のツール（未指定の文言の `--from` に使う）。フック（3.1）はここに指揮役のツールを渡す。拒否の理由は 7 種ごとに固有の文言と、共通の案内の 4 条件を持つ。設定が壊れているときは `messageConfigBroken(problems)`。
- 2.3: `renderDefinitions(cfg)` → `{files, notices}`。Claude Code の定義は `roles.claude` だけから作り、説明文は同じ提供元の `defaultModelFor` の逆引き（予備のレビューは Sonnet→haiku・Opus→sonnet・Fable→opus）。model は YAML の二重引用。本文は `instructionFor(role, permission)` で権限を反映。Claude Code が受け付ける推論量はファイル内の `CLAUDE_EFFORTS` で判定している（2.4 で作る受け付けの判定と統一する）。
- 2.4: `buildCliCommand(target, {permission, effort}, modelName, root)` の effort は解決済みの値を渡す。`effortSupported(vendor, effort, levels)` は Codex で一覧（配列）があればその内容だけで判定する。2.3 の `CLAUDE_EFFORTS` は `effortSupported` に統一済み。
- 3.1: 設定は ENOENT だけ既定で判定し、ほかの読み取りの失敗は起動を拒否する。会話の記録が読めなければ指揮役を不明として続ける。定義の名前は `^[A-Za-z0-9_][A-Za-z0-9_.-]*$` だけ受け付ける。TOML は最上位の `model`・`model_reasoning_effort`（引用符付きのキーも）だけを読む。役割定義のファイルの EACCES などは標準エラーに出して通す。
- 3.2: `delegate.mjs` の `--resolve-model` は標準出力に 1 行 `<名前> <推論量>`、知らせは標準エラーに `知らせ: …`、止める場合は `delegate: <理由>` で終了 2。通常の指定は確かめを通った後、今は「子の起動はまだ作られていません（タスク 3.4）」で終了 2（3.4 で起動に置き換える）。`decide()` の戻り値（name・effort・target・permission）は確かめ済みで `buildCliCommand` に渡せる。Claude Code の組み込みの子の名前を求める指定に `--model`・`--effort` を付けると終了 2（Codex の組み込みの子では反映する）。入口の `tiersOf` は subagent-roles の格の表の重複（`mergedTiers` が未公開のため）。
- 3.3: 実機で Claude Code・Codex のフックの拒否と通過を確認（`poc/subagent-defs/` の d・e、OK 13・NG 0）。途中で、Codex のサンドボックスでは Node の `spawnSync` が子の標準入力のパイプを閉じるときに EPERM が `r.error` に載ることが分かり（`codex debug models` は成功しているのに一覧を捨てていた）、`fetchCatalog` の標準入力を使わない形に直した。3.4 で子の CLI に指示を渡すときも、パイプに書いて閉じる形を避け、ファイルを開いた記述子を標準入力にするなど同じ EPERM を起こさない形にする。Codex の子の記録は `session_meta` の `agent_path`（`/root/<task_name>`）と `parent_thread_id` で起動と対応づけられる（Codex 0.167.0）。
- 3.4: 子は `stdio: [指示のファイルの記述子, "inherit", "inherit"]`・`cwd: 根` で起動し、指示のファイルは通常のファイルか `fstatSync` で確かめる。`claude` を起動するときだけ `CLAUDE_CODE_EFFORT_LEVEL`・`CLAUDE_EFFORT`・`CLAUDECODE`・`CLAUDE_CODE_ENTRYPOINT` を外す。`--to` は `same` だけ（別の提供元は役割設定の `provider` で選ぶ）。`--to same` と委任先に属さないその実行の `--model` の併用は終了 2。
- 3.5: 区画の書き直しは `decideInstall` の `rewrite-section`（材料 `sectionStale`）と `performSectionRewrite`（導入中の印を取って読み直し、文書ごとに一時ファイル → rename、配置物の文章の目印を書き込む直前に検証）。書き直しの経路の失敗はすべて `SectionRewriteError` で、失敗の記録を作らない。4.1 でカタログに登録するまで、`node bin/cc-sdd-bootstrap.mjs update` は未登録の配置物（delegate.mjs・subagent-check.mjs）を消すので実行しない。
