# 要件文書

## Project Description (Input)

cc-sdd の利用者は、実装・修正、レビュー、設計、調査、デバッグをサブエージェント（子のエージェント）に任せる。役割に合ったモデルと権限を使い、指揮役（会話を進めるメインのエージェント）のモデルを意図せず引き継ぐ起動を防ぐ必要がある。また、Claude Code と Codex のどちらが指揮役でも、別の提供元の子を積極的に利用できるようにする。

役割ごとの提供元・モデル・推論量（モデルが考える量の設定）・権限を共通の役割表で定める。その設定を両方の利用環境の役割定義に反映し、組み込みの子ではモデルの未指定と指揮役との一致を起動前に拒否する。別の提供元への委任では、役割と指示のファイルを渡す入口を利用する。Claude Code が指揮役なら `codex exec`、Codex が指揮役なら `claude -p` を使う方針とし、委任時の指示と結果確認の手順は文章で示す。

厳密さのための管理機構を増やさず、役割設定、役割定義、起動拒否、別の提供元への委任に範囲を絞る。

## Introduction

本仕様は、cc-sdd の委任で使う役割と起動条件を共通化する。以下では、この振る舞いを提供する仕組みを「サブエージェント委任機能」と呼ぶ。組み込みの子とは、Claude Code または Codex 自身が提供する子のエージェントを指す。

> 改訂（2026-11-23）: 旧版は目的の説明のみだったため、単純化後の brief に沿って受け入れ基準を新設した。撤回した前身の入口認証・接続先の探査・ジョブ管理・自動切り替え・直接呼びの拒否は引き継がず、役割表、両環境の役割定義、モデルの起動拒否、別提供元への委任とその手順に絞った。

## 対象と境界

- **対象**: 実装・修正、レビュー、設計、調査、デバッグの役割設定と既定値、その設定を反映した役割定義、すべての組み込みの子のモデル確認、別提供元への委任と手順。
- **対象外**: MCP（外部ツールの接続口）の探査と候補順位、自作の接続サーバー、ジョブの記録・状態確認・別プロセスからの停止、合言葉や引数照合による入口認証、委任先の自動切り替え、端末上のローカルモデル、入口を通さない直接呼びの拒否、cc-sdd 本体の改変・再配布。
- **隣接仕様**: installer-core が設定の初期作成・配置・フックの登録・運用の区画の文章の配置を扱い、session-install が導入のたびに CLAUDE.md・AGENTS.md へ運用の区画を書き足す。session-install が cc-sdd 本体の導入を扱う。kiro-gate が手順書を読むまでの操作拒否を扱う。
- **強制の限界**: 起動前の自動確認には、利用環境でフック（操作前に確認を行う仕組み）が有効であることが必要となる。Codex で必要な信頼の承認がない場合は、手順の文章で補う。書き込みの並行禁止は手順として示し、実行状況を追跡する機構は設けない。

## Requirements

### Requirement 1: 共通の役割設定と既定値

**目的:** 利用者が役割に合うモデル・推論量・権限を設定し、委任方法が変わっても同じ役割の条件を使えるようにする。

#### 受け入れ基準

1. When 利用者が役割設定を行うとき, the サブエージェント委任機能 shall 実装・修正、レビュー、設計、調査、デバッグについて、利用する提供元と、その提供元で使うモデル・推論量・権限を指定できるようにする。
2. When 同じ役割を組み込みの子または別提供元の子へ委任するとき, the サブエージェント委任機能 shall 選んだ提供元について共通の役割設定を使用する。
3. When 実装・修正、レビュー、調査、デバッグの役割設定の項目が省略されているとき, the サブエージェント委任機能 shall 省略された項目に以下の既定値を適用する。

   | 役割 | Codex のモデル | Claude Code のモデル | 推論量 | 作業先の権限 |
   |---|---|---|---|---|
   | 実装・修正 | `gpt-6-luna` | Haiku | `medium` | 書き込み可 |
   | レビュー | `gpt-6.1-sol` | Sonnet | `medium` | 読み取り専用 |
   | 調査 | `gpt-6.1-sol` | Sonnet | `medium` | 読み取り専用 |
   | デバッグ（原因調査） | `gpt-6.1-sol` | Sonnet | `medium` | 読み取り専用 |

4. When 設計役の設定の項目が省略されているとき, the サブエージェント委任機能 shall 省略された項目に、Codex では `gpt-6.1-sol`、Claude Code では Sonnet、推論量は `high`、作業先の権限は読み取り専用を適用する。
5. When 利用者が役割設定の一部を明示しているとき, the サブエージェント委任機能 shall その値を既定値で置き換えずに使用する。
6. If 役割設定を読み取れない、または必要な設定値を確定できないとき, the サブエージェント委任機能 shall その設定による定義の更新または委任を行わず、問題のある項目を利用者に示す。

### Requirement 2: 両方の利用環境で使える役割定義

**目的:** 利用者が Claude Code と Codex のどちらを指揮役にしても、役割に対応する組み込みの子を選べるようにする。

#### 受け入れ基準

1. When 役割設定を導入または更新するとき, the サブエージェント委任機能 shall Claude Code と Codex のそれぞれで、その提供元の役割設定を反映した組み込みの子の定義を利用できるようにする。
2. When 指揮役が組み込みの子へ委任するとき, the サブエージェント委任機能 shall 依頼の役割に対応する定義と、そのモデル・推論量・権限を確認できるようにする。
3. If 指定されたモデル・推論量・権限を対象の利用環境で適用できないとき, the サブエージェント委任機能 shall 適用できない項目を示し、別の条件へ黙って置き換えて起動しない。

### Requirement 3: モデルの未指定と指揮役との一致の拒否

**目的:** モデルの意図しない引き継ぎや、指揮役と同じモデルによる子の起動を防ぐ。

#### 受け入れ基準

1. While 起動前の自動確認が有効であるとき, the サブエージェント委任機能 shall 本仕様が提供する役割に限らず、対象プロジェクトでのすべての組み込みの子の起動をモデル確認の対象とする。
2. If 確認対象の起動で子のモデルが未指定、または指揮役からの引き継ぎ指定であるとき, the サブエージェント委任機能 shall 子の起動を拒否する。
3. If 確認対象の起動で子と現在の指揮役が同じモデルになると確認できるとき, the サブエージェント委任機能 shall 子の起動を拒否する。
4. When 指揮役のモデルの変更を確認した後に次の確認対象の起動が行われるとき, the サブエージェント委任機能 shall 変更後のモデルを比較に用いる。
5. If 指揮役の現在のモデルを確認できず、子のモデルは明示されているとき, the サブエージェント委任機能 shall 指揮役のモデルが不明であることだけを理由には起動を拒否しない。
6. When モデルの未指定、引き継ぎ、または指揮役との一致により起動を拒否するとき, the サブエージェント委任機能 shall 拒否理由と、指揮役と異なるモデルを明示する必要があることを指揮役へ伝える。
7. When モデル確認によって起動を拒否しないと判定したとき, the サブエージェント委任機能 shall kiro-gate による手順書の未読を理由とする拒否を解除しない。

### Requirement 4: 役割設定に従った別提供元への委任

**目的:** 指揮役を切り替えても、既存の実行手段で別提供元の子へ作業を任せられるようにする。

#### 受け入れ基準

1. When 指揮役が役割と指示のファイルを指定して別提供元への委任を求めるとき, the サブエージェント委任機能 shall Claude Code が指揮役なら Codex、Codex が指揮役なら Claude Code の子へ委任できるようにする。
2. When 別提供元の子を起動するとき, the サブエージェント委任機能 shall 指定された役割について、その提供元の設定済みモデル・推論量・権限を適用する。
3. When 別提供元の子へ依頼を渡すとき, the サブエージェント委任機能 shall 指定された指示の内容と対象リポジトリの作業場所を子へ渡す。
4. When 書き込み可の役割で委任するとき, the サブエージェント委任機能 shall 対象の作業先で編集とテスト実行を許可する。
5. When 読み取り専用の役割で委任するとき, the サブエージェント委任機能 shall 子による対象の作業先への書き込みを許可しない。
6. When 委任先の実行が終了したとき, the サブエージェント委任機能 shall 委任先の応答と、実行が成功したか失敗したかを指揮役へ返す。
7. If 役割が未定義、指示のファイルを読めない、委任先を起動できない、または指定した条件を適用できないとき, the サブエージェント委任機能 shall 理由を返し、別の提供元・モデル・推論量・権限で自動的にやり直さない。

### Requirement 5: 委任と結果確認の手順の共有

**目的:** 指揮役が共通の手順で別提供元の子を使い、返された結果を確認してから作業を完了できるようにする。

#### 受け入れ基準

1. When Claude Code または Codex 向けの委任手順を提供するとき, the サブエージェント委任機能 shall 別提供元の子を優先して利用し、利用できない場合は指揮役が組み込みの子への委任を判断する手順を示す。
2. When cc-sdd の手順が組み込みの子への委任を指示しているとき, the サブエージェント委任機能 shall 同じ依頼内容と成果物の形式を保って別提供元の子へ渡す読み替えを、指揮役向けの文章で示す。
3. When 指示のファイルの準備方法を案内するとき, the サブエージェント委任機能 shall そのファイルを `~/.cache/cc-sdd-bootstrap-scratch/` に置き、リポジトリ内と `/tmp` には置かない手順を示す。
4. When 子への指示の作成方法を案内するとき, the サブエージェント委任機能 shall 依頼の範囲、必要なプロジェクトの決まり、禁止する操作、成果物の形式を指示へ含め、子が指揮役の指示書を読むことに依存しない手順を示す。
5. When 書き込み可の子を使う手順を案内するとき, the サブエージェント委任機能 shall 書き込み可の子の実行を1つずつ行い、その実行中に読み取り専用の子の実行も重ねない決まりを示す。
6. When 子の結果を受け取った後の手順を案内するとき, the サブエージェント委任機能 shall 結果を未確認として扱い、変更差分と対象の作業に必要なテストを確認してから完了と判断する手順を示す。
7. When Codex が指揮役で、別提供元の子（Claude Code）を使う手順を案内するとき, the サブエージェント委任機能 shall 指揮役のシェルから子が通信できる許可が必要であることと、許可が無いと子が応答を返せないことを示す。
8. Where Codex のフックに必要な信頼の承認が与えられていない環境を扱うとき, the サブエージェント委任機能 shall 自動確認が働かないことと、役割設定に従いモデルを明示して指揮役と同じモデルを避ける手順を、指揮役向けの文章で示す。
