# Requirements Document

## Project Description (Input)
cc-sdd を運用するプロジェクトでは、製造・レビュー・設計などにサブエージェントを使う。現状は呼び出し方がクライアントごとの指示に依存し、モデルを指定しない起動が指揮役のモデルを引き継ぐことがある。役割ごとにモデル・推論量・作業権限を設定し、ネイティブ定義と外部委任から共通の役割条件を参照できるようにする。指揮役と同じモデルや意図しない引き継ぎでの起動を防ぐ。

## Introduction

cc-sdd の利用者が作業に合ったモデルと権限でサブエージェントを使い、指揮役のモデルを意図せず引き継ぐ起動を防げるようにする。役割と適格条件をネイティブ起動と外部委任で共用する。

> 改訂（2026-11-22、再承認待ち）: 要件 1〜4 は実装済み。下流の codex-delegation の実機検証（`poc/codex-delegation-live/result.md`）で、上流の部品に起因する 2 つの問題が見つかったため、要件 5（管理入口への呼び出し参照の付け足し）と要件 6（ネイティブ単独の事前確認での外部候補の判定）を追加した。既存の番号は変えていない。追加分は未実装で、要件・設計・タスクの承認をやり直す。影響は `design.md` の「変更の影響（2026-11-22 の改訂）」を参照する。

## Boundary Context

- **対象** — cc-sdd の委任で使う役割とその設定、Claude Code と Codex のネイティブ定義、起動モデルの確認。管理入口（下流が配置する委任入口を含む）への呼び出し参照の発行・付け足し・消費の規則と、ネイティブ単独の事前確認を発行できる条件。
- **対象外** — MCP の登録・探査と候補の優先順位、cc-sdd 本体のスキルの改変。
- **隣接仕様** — installer-core は利用者設定の保存と導入・更新を扱う。codex-delegation はここで定める役割条件と外部 MCP の公開情報を照合する。委任入口の処理内容、委任設定（`delegation`）の保存形式、外部 MCP の直接起動の拒否は codex-delegation が扱い、本仕様はその入口の呼び出しの決まった形と保存形式を読むだけとする。kiro-gate の手順確認は引き続き適用する。

## Requirements

### Requirement 1: 共通の役割と適格条件

**目的** — cc-sdd の利用者が、委任先を切り替えても役割の意味と作業権限を維持できるようにする。

#### Acceptance Criteria

1. The サブエージェントポリシー shall 製造（実装・修正）、レビュー、設計、調査、デバッグの依頼について、ネイティブ起動と外部委任で共通の役割条件を参照できるようにする。
2. When 製造役に実装または修正を依頼するとき, the サブエージェントポリシー shall 指定した作業先での編集とテスト実行を必要権限として扱う。
3. When レビュー、調査、原因調査としてのデバッグを依頼するとき, the サブエージェントポリシー shall 読み取り専用を必要権限として扱う。
4. When 設計の依頼が読み取り専用を必要とするとき, the サブエージェントポリシー shall その指定を役割条件に含める。
5. When ローカル MCP の公開モデルを役割に割り当てるとき, the サブエージェントポリシー shall その役割のモデル条件と必要な推論量に適合する公開モデルだけを候補にする。

### Requirement 2: 役割ごとのモデルと推論量

**目的** — 利用者が設定を省略しても作業に応じた既定値を使え、必要な役割だけを上書きできるようにする。

#### Acceptance Criteria

1. The サブエージェントポリシー shall 利用者が役割ごとのモデルと推論量を設定し、設定済みの値を確認できるようにする。
2. When 製造役のモデルまたは推論量を省略したとき, the サブエージェントポリシー shall 省略された項目に、Claude Code では Haiku、Codex では Luna、推論量は `medium` を適用する。
3. When レビュー役のモデルまたは推論量を省略したとき, the サブエージェントポリシー shall 省略された項目に、Claude Code では Sonnet、Codex では Sol、推論量は `medium` を適用する。
4. When 設計役のモデルまたは推論量を省略したとき, the サブエージェントポリシー shall 省略された項目に、Claude Code では Sonnet、Codex では Sol、推論量は `high` を適用する。
5. When 利用者が製造役またはレビュー役の推論量に `high` を指定し、そのモデルが対応しているとき, the サブエージェントポリシー shall 指定された推論量を適用する。
6. When 導入済みのプロジェクトでモデル設定を見直すとき, the サブエージェントポリシー shall 既存の役割別モデル指定を含め、利用者が明示した役割設定を引き継ぐ。

### Requirement 3: ネイティブエージェントの選択

**目的** — 外部の委任先を使えない場合にも、現在のクライアントで役割に対応するサブエージェントを使えるようにする。

#### Acceptance Criteria

1. When Claude Code または Codex を対象に導入・更新するとき, the サブエージェントポリシー shall 設定済みの役割に対応するネイティブ定義を利用できるようにする。
2. When ネイティブサブエージェントを使うとき, the サブエージェントポリシー shall 指揮役にその依頼の役割に対応する定義を示す。
3. If 現在のクライアントで指定のモデル・推論量・必要権限を適用できないとき, then the サブエージェントポリシー shall 適用できない項目を示し、その設定でサブエージェントを起動しない。

### Requirement 4: 指揮役と同じモデルでの起動防止

**目的** — 利用者が意図しないモデルの引き継ぎや重複起動を防ぎ、拒否された理由を確認できるようにする。

#### Acceptance Criteria

1. When cc-sdd の役割でネイティブサブエージェントを起動する直前, the サブエージェントポリシー shall 現在の指揮役と起動予定のサブエージェントのモデルを比較する。
2. If 起動予定のサブエージェントが指揮役のモデルを引き継ぐか、名前や別名が異なっても指揮役と同じモデルになるとき, then the サブエージェントポリシー shall 起動を拒否する。
3. When 指揮役のモデルをセッション中に切り替えたとき, the サブエージェントポリシー shall 次の起動判定に切り替え後のモデルを用いる。
4. When モデルの引き継ぎまたは一致を理由に起動を拒否したとき, the サブエージェントポリシー shall 拒否理由と、該当する役割で利用できる別設定がある場合はその選択肢を示す。

### Requirement 5: 管理入口への呼び出し参照の付け足し

**目的** — 指揮役のモデルが一回限りの参照（呼び出しを現在のセッション・ターンに結び付ける使い捨ての合言葉）を見たり書いたりせずに、管理入口を使えるようにする。ここでいう管理入口は、本仕様の作業コンテキストの入口（`kiro-delegation-context.mjs enter` / `preflight`）と、codex-delegation が配置する委任入口（`delegate.mjs start` / `status` / `stop`）を指す。

#### Acceptance Criteria

1. When 指揮役が管理入口を決まった形のシェル呼び出し（Bash）で、参照を付けずに呼ぶとき, the サブエージェントポリシー shall ホストのツール起動前フック（PreToolUse）で現在のセッション・ターンに結び付いた参照を発行し、呼び出しに付け足してから実行させる。
2. The サブエージェントポリシー shall 発行した参照を指揮役のモデルの入力・出力に含めない。
3. If 管理入口への呼び出しにモデル自身が書いた参照が含まれるとき, then the サブエージェントポリシー shall その呼び出しを拒否する。
4. If 管理入口を指すシェル呼び出しが決まった形から外れるとき（命令の連結、リダイレクト、別名、未知の引数など）, then the サブエージェントポリシー shall 呼び出しを書き換えずに拒否し、決まった形を理由で示す。
5. If 管理入口が参照なし、使用済みの参照、または別のセッション・ターンの参照で実行されたとき, then the サブエージェントポリシー shall その入口に処理を行わせず、理由を返させる。
6. The サブエージェントポリシー shall 要件 5.1〜5.5 を Claude Code と Codex の両方に同じ規則で適用する。
7. If 対象のホストで参照の付け足しと、参照がモデルに見えないことを実機で確認できていないとき, then the サブエージェントポリシー shall そのホストでは参照を付け足す経路を管理された経路として公開しない。

### Requirement 6: ネイティブ単独の事前確認での外部候補の判定

**目的** — 外部の委任先を実際には使わない構成で、委任機能の部品が置かれているだけを理由にネイティブの事前確認が拒否されないようにする。外部の委任先を使う構成では、引き続き管理入口を通す。

#### Acceptance Criteria

1. When ネイティブ単独の事前確認（`preflight`）を発行するとき, the サブエージェントポリシー shall 外部委任の有無を、導入台帳（配置したファイルの記録）に特定のファイルがあるかではなく、プロジェクト設定に保存された有効な外部候補があるかで判定する。
2. The サブエージェントポリシー shall 有効な外部候補を、設定の `delegation[<現在のホスト>].cloud` に保存された候補（この項目が未設定の場合は、`codex.enabled` が有効なときに引き継ぐ管理対象の Codex MCP）から、現在のホストと同じ系統の候補を除いたものとして求める。
3. If 有効な外部候補が 1 つ以上あるとき, then the サブエージェントポリシー shall 単独の事前確認を発行せず、管理入口を使うよう理由で示す。
4. When 有効な外部候補がないとき, the サブエージェントポリシー shall 委任機能の部品が配置されていても、ほかの検査を満たす限り単独の事前確認を発行する。
5. If 設定を読み取れないか、委任の設定が形式に合わないとき, then the サブエージェントポリシー shall 単独の事前確認を発行しない。
6. The サブエージェントポリシー shall 要件 6.2 の判定に設定ファイルの中身だけを使い、委任機能の配置物の読み込みやホストの命令の実行を行わない。
