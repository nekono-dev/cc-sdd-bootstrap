  - 予約役割、実効モデル、推論量、権限の証拠を照合する。別名解決済みの一致、継承、定義不一致、証拠不足のときは拒否する。
  - 許可・拒否の結果と、拒否理由および適格な代替がある場合の案内を単体で確認する。

- [ ] 2.3 cc-sdd の作業を識別して管理入口に引き継ぐ
  - 正規の明示呼び出し・手順読み取り・管理入口で管理状態を開始し、通常の作業と別セッションを区別する。
  - 正規化済みの作業ツリー、クライアント、セッション、ターンごとに記録を隔離する。委任先が書き込めない実行時領域を使い、別の作業ツリーの記録を拒否できることを確認する。
  - ホスト由来の呼び出し参照を一度だけ使えるようにする。終了後に前のターンの参照が失効し、自己申告したセッションでは起動できないことを確認する。
  - _Boundary: KiroDelegationContext_
  - _Depends: 2.2_
  - _Requirements: 3.2, 3.3, 4.1, 4.2_

- [ ] 2.4 ネイティブ起動の事前確認を一回だけ発行・消費できるようにする
  - 役割、呼び出し、引数、セッション、ターンを候補選択と照合して記録を発行する。
  - 事前確認記録は原子的に消費し、二つの同時起動要求で許可が最大一回になることを確認する。再利用、別ターン、組み込み・役割なしを拒否し、通常作業は既存の判断に任せる。
  - 単独導入で使える発行経路を用意する。委任機能の配置後は単独発行を無効にし、配置状態が不明なら発行しないことを確認する。
  - _Boundary: KiroDelegationContext, NativeAgentGate（統合）_
  - _Requirements: 3.2, 3.3, 4.1, 4.2, 4.4_

- [ ] 2.5 Claude Code のセッションとモデル変更を起動判定に接続する
  - 作業範囲を起動イベントから参照し、セッション初期化とモデル変更を記録する。起動フックで別セッションの値や変更前の値を使わないようにする。モデル観測は原子的に置換し、途中の書き込みでは有効な証拠が得られないことを確認する。
  - モデル不明、変更中、変更後、起動時の指定による不一致を模擬入力で確かめ、判定不能時に起動拒否と理由が返ることを確認する。
  - _Boundary: NativeAgentGate_
  - _Requirements: 3.3, 4.1, 4.2, 4.3, 4.4_

- [ ] 2.6 Codex の起動引数と権限の証拠を判定に接続する

  - 履歴引き継ぎ、別ターンの記録、昇格可能な読み取り専用、判定不能を拒否し、適格な別モデルと権限なら通常の承認へ進むことを確かめる。
  - _Boundary: NativeAgentGate_
  - _Requirements: 1.3, 3.3, 4.1, 4.2, 4.3, 4.4_

## Implementation Notes

- 2.3–2.6 は作業範囲と起動判定の記録や配置物を共有するため順に実施する。3.1 と 3.2 は導入の管理範囲と登録に依存関係があるため順に実施する。
- 4.2 と 4.3 の前提は、承認済み設計と設計時の PoC で使用したクライアント、認証、一時リポジトリを作成できる環境。1.1 で実行環境と既存 PoC の入口を確認する。

- 1.1 を確認した環境は Node.js 22.16.0、Claude Code 2.1.329、Codex CLI 0.167.0。独立した実行環境で両クライアントの実機 PoC と模擬 API が成功した。委任エージェントの子プロセスではネットワークまたはループバックが制限されるため、実機の再検証は親が行う。
