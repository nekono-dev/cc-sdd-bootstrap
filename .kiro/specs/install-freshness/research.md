# 調査記録: install-freshness

## 調査の範囲
- 種別: 既存の導入・更新の仕組みへの拡張（軽い調査）＋外部の動作の前提の確認（PoC）。
- 調べたもの: `lib/plan.mjs`・`lib/target.mjs`・`lib/catalog.mjs`・`lib/cli.mjs`（導入の流れ）、`install-cc-sdd.mjs`（セッション開始のフック）、`poc/session-hooks/`・`poc/codex-hook-trust/`（既存の根拠）。

## 外部の動作の前提と根拠
詳細・実行手順は `poc/install-freshness/result.md`（2026-11-26、Node.js 22.16.0、npm 10.9.2、Claude Code 2.1.329、Codex CLI 0.172.0）。

| 前提 | 結果 | 設計への反映 |
|---|---|---|
| `npx github:…#ref` で取得した配布物から配布元のコミットを取り出せる | 配布物の 1 つ上の `.package-lock.json` の `resolved` に 40 桁のコミット（A2・A3）。`package.json` には無い（A4） | `source.mjs` がそこから取り出す。取り出せなければ `commit: null` |
| 取得時の指定（ブランチ・タグ）を取り出せる | 2 つ上の `package-lock.json` の依存の書き方に残る（A5） | ブランチ指定の利用先は、そのブランチの先頭と比べる |
| `npx` のキャッシュが古い版を返し続ける | 枝指定は実行のたびに解決し直され、再現しなかった（手動の確認） | 記録は「実際に配置した版」とし、最新と偽らない |
| 最新を安く取得できる | `git ls-remote`（認証不要、約 1.3 秒）。失敗・非公開は非 0（B1・B2・B4）。待ち時間は呼び出し側で打ち切れる（B3） | 3 秒で打ち切り、失敗は比較を省く |
| SessionStart の追加の文脈がエージェントに届く | Claude Code・Codex の両方で届く（D） | 追加の文脈で案内し、利用者へ伝える指示を文面に入れる |

## 設計の判断（要約）
- 記録は配置物と同じ場所（`.agent-hooks/cc-sdd-bootstrap/install-record.json`）に置き、コミット対象にする。導入先で配置物と一緒に動き、`git diff` で見える。
- 新しいフックは session-install から独立させる。鮮度の検知の失敗が導入の判断や入力の停止に影響しないようにするため。
- 記録の形・指紋の計算は純粋部品 1 か所に置き、導入側（`lib/`）と照合側（配置物）の両方が使う。
- 手元の checkout からの実行（自己適用）はコミットを取り出せないため `commit: null` とし、最新との比較は行わない。`commit: null` だけでは案内を出さない（ずれが無い自己適用で毎回案内しないため）。

## 簡素化の検討（合成）
- 一般化: 照合の対象をカタログの配置物と運用の区画の 2 ファイルに限り、フック登録・`.gitignore`・サブエージェント定義は含めない（要件の範囲外。必要になったら別の仕様）。
- 作らないもの: 利用者が編集したかの検出、自動更新、キャッシュの無効化、複数の配布元への対応、設定ファイルでの on/off（既存の関門の設定は「止める」ものに付いており、案内だけの本機能には付けない）。
- 買う・採用するもの: なし（標準モジュールと `git` のみ）。

## リスク
- 追加の文脈は、エージェントが利用者へ伝えるかに依る。案内文に伝える指示を入れ、実機で確認する（場面 D の延長）。
- `.package-lock.json` の配置は npm の版に依る可能性がある。取り出せない場合は `commit: null` に倒れ、検知が弱まるだけで動作は止まらない。
