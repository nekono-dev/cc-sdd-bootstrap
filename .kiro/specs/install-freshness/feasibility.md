# 実現性の記録: install-freshness

## 実機検証の要否
- 判定: 必要
- 理由: 外部の動作に依存する前提がある。(1) 導入コマンドを `npx` で取得した配布物から、配布元の版（コミット）を取り出せるか。(2) `npx` のキャッシュに古い版が残るとき、更新で古い配置物が書かれるか。(3) 配布元の最新の版を、通信で安く取得できるか（待ち時間・未認証・失敗時の挙動）。(4) セッション開始のフックの出力（案内）が Claude Code・Codex の両方で利用者へ届くか。前提ごとに PoC を作る。

## 設計の確認
- 判定: 通過
- 根拠:
  | 前提 | 根拠の種別 | 出典・PoC（場所と版／実行日・環境・結果） |
  |---|---|---|
  | `npx github:…#ref` で取得した配布物から配布元のコミットを取り出せる（配布物の 1 つ上の `.package-lock.json`）。`package.json` には版以外の識別情報が無い | 実機の PoC | `poc/install-freshness/result.md` の A1〜A4（2026-11-26、Node.js 22.16.0・npm 10.9.2） |

  | 配布元の最新を `git ls-remote` で認証なしに取得できる。失敗・待ち時間超過で打ち切れる | 実機の PoC | 同 B1〜B4 |
