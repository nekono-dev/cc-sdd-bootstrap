# 要件文書

## Project Description (Input)

**対象となる利用者**：cc-sdd（仕様を書いてから設計・実装を進めるための外部ツール）の運用を、複数のリポジトリへ導入・更新する開発者。

**解決する問題**：既存の導入コマンドは、配置記録、改変の検出、汎用の取り除き計画、対話による設定などを持ち、共通の配置物を写す用途に対して複雑になっている。また、Claude Code だけに対応しており、Codex を指揮役として利用する準備を揃えられない。

**目指す状態**：

- 1 回のコマンドで、Claude Code と Codex の両方に運用一式を配置・更新できる。
- 共通の配置物は直接編集しない生成物として扱い、再実行で導入コマンドの版に揃える。差分は利用者が git で確認する。
- 設定は `.cc-sdd-bootstrap.json` に既定値で作り、利用者が直接編集する。
- 利用者のフックと、`.gitignore` の管理対象外の内容を保つ。
- CLAUDE.md・AGENTS.md は cc-sdd の標準の文書として導入のたびに作り直し、コミットしない。プロジェクト独自の決まりは `.kiro/steering/` に置く。
- cc-sdd 本体を同梱せず、その導入物をコミット対象から除外する。

**対象外**：配置記録と改変の検出、強制上書きの指定、汎用の取り除き計画、対話による聞き取り、後続仕様向けの汎用の拡張点。cc-sdd 本体の取得と各フックの実行時の振る舞いは、隣接仕様で扱う。

## Introduction

導入コマンドは、cc-sdd を利用するための共通の配置物、設定ファイル、フック（決まった時点で処理を呼ぶ仕組み）の登録、CLAUDE.md と AGENTS.md の末尾に書き足す運用の区画の文章、`.gitignore` の除外設定を揃える。Claude Code と Codex の両方を指揮役として利用する準備を、同じ操作で行えるようにする。

> 改訂（2026-11-23）: 旧版の配置記録・改変検出・強制上書き・対話・汎用の拡張点を外し、Codex のフック登録と AGENTS.md の管理区画を追加した。取り除き（`uninstall`）はフックの登録と運用の区画を外すだけに限定した。廃止した配置物は、更新のたびに共通の配置物を初めから入れ直すことで片付け、廃止の一覧は持たない。
>
> 改訂（2026-11-23、利用者の指示）: 利用者の CLAUDE.md・AGENTS.md を保って管理区画を足す形をやめた。CLAUDE.md・AGENTS.md は cc-sdd の導入で標準の文書として書き出し、その後に session-install が運用の区画（目印の行で囲んだ cc-sdd-bootstrap の案内）を末尾へ書き足す。両文書はコミットせず、プロジェクト独自の決まりは `.kiro/steering/` に置く。本仕様は運用の区画の文章の配置と、既存の文書がある場合の案内を担う。

共通の配置物は生成物であり、直接編集しない。利用者が変更する設定ファイルと、文書・設定の管理対象外の部分は、共通の配置物とは区別して扱う。

## 対象と境界

- **対象**：固定された一式の配置・更新、設定ファイルの初期作成と最小限の検証、両ツールのフック登録、CLAUDE.md・AGENTS.md に書き足す運用の区画の文章、`.gitignore`、自己適用。
- **対象外**：cc-sdd 本体の同梱・改変・取得、配置記録の作成、配置後の改変検出、`--force`、対話による設定、汎用の削除計画や拡張機構、他プロジェクト固有の移行、プラグインとしての配布。
- **session-install との関係**：本仕様は導入処理の入口と運用の区画の文章を配置する。CLAUDE.md・AGENTS.md の書き出しと運用の区画の書き足しは、cc-sdd の導入のたびに session-install が行う。起動前・初回の cc-sdd の導入、版・言語に応じた取得、失敗時の停止、再試行と導入直後の案内内容は session-install が定める。
- **kiro-gate との関係**：本仕様はフックの登録と案内の文章を配置する。手順書を読むまでの拒否と、自然文の依頼に対応するスキルの案内内容は kiro-gate が定める。
- **subagent-delegation との関係**：本仕様は必要な配置物・登録・文章を配置する。役割表の内容、エージェント定義の生成、子のモデルの判定、別ベンダの起動は subagent-delegation が定める。
- **Codex の利用条件**：フックを働かせるには利用者による信頼の承認が必要となる。設定の具体的な置き場所・形式・承認の扱いは、設計前に実際の動作で確認する。

## Requirements

### Requirement 1: 導入・更新の操作

**目的**：利用者が、対話による聞き取りなしに、同じコマンドで運用一式を導入・更新できる。

#### 受け入れ基準

1. When 利用者がリポジトリの最上位で `npx github:nekono-dev/cc-sdd-bootstrap init` を実行した, the 導入コマンド shall Claude Code と Codex の両方に必要な運用一式を配置する。
2. When 利用者が導入済みのリポジトリで `update` を実行した, the 導入コマンド shall 既存の設定値を保ち、共通の配置物・フック登録・除外設定を実行した版の内容に揃える。
3. If `init` の対象に設定ファイルが既にある, the 導入コマンド shall ファイルを変更せず、更新には `update` を使うよう案内する。
4. If `update` の対象に設定ファイルが無い, the 導入コマンド shall ファイルを変更せず、初回には `init` を使うよう案内して失敗として終わる。
5. When 設定と一式の内容が変わらない状態で `update` を再実行した, the 導入コマンド shall ファイルの内容を変えず、変更が無いことを表示する。
6. When `init` または `update` を実行した, the 導入コマンド shall 対話による質問をせずに処理する。
7. When 利用者が使い方の表示を求めた, the 導入コマンド shall ファイルを変更せず、利用できる操作と設定ファイルの編集方法を表示する。
8. If 未知の操作や未対応の指定が渡された, the 導入コマンド shall ファイルを変更せず、問題の指定と使い方を表示して失敗として終わる。

### Requirement 2: 設定ファイルの初期作成と保持

**目的**：利用者が、プロジェクトごとの設定を 1 つのファイルで読み書きし、更新後も使い続けられる。

#### 受け入れ基準

1. When 設定ファイルが無い状態で `init` を実行した, the 導入コマンド shall リポジトリの最上位に `.cc-sdd-bootstrap.json` を既定値で作成する。
2. When 設定ファイルを作成した, the 導入コマンド shall 使用した既定値と、変更するには設定ファイルを直接編集することを表示する。
3. When `update` が設定ファイルを読み込んだ, the 導入コマンド shall 今回の操作に必要な項目について、必須値の有無と許される種類・値を確認する。
4. If 設定ファイルが読めない、または必要な項目が不正である, the 導入コマンド shall ファイルを変更せず、ファイル名・問題箇所・理由を表示して失敗として終わる。
5. When 既存の設定ファイルを使って更新した, the 導入コマンド shall 利用者が記入した値と、今回の操作で使わない項目を変更せずに残す。

### Requirement 3: 共通の配置物と更新の扱い

**目的**：利用者が、共通の配置物を直接保守せず、コマンドの再実行で揃えられる。

#### 受け入れ基準

1. When `init` または `update` を実行した, the 導入コマンド shall この版が配置対象とする共通の配置物を、実行に必要な状態で作成または置き換える。
2. When 配置対象と同じ場所に既存の共通ファイルがある, the 導入コマンド shall 強制上書きの指定を求めず、この版の内容で置き換える。
3. When 配置方法を案内した, the 導入コマンド shall 共通の配置物は直接編集しないことと、更新の差分を git で確認することを示す。
4. When 旧版の共通の配置物がある対象で `update` を実行した, the 導入コマンド shall 共通の配置物の置き場所を初めから入れ直し、この版に含まれない旧版の共通の配置物を残さない。廃止した配置物の一覧や旧版の配置記録は使わない。
5. The 導入コマンド shall cc-sdd 本体のスキルや雛形を、共通の配置物として同梱しない。

### Requirement 4: 両ツールのフック登録

**目的**：利用者が、既存の設定を保ちながら、Claude Code と Codex の両方で運用一式を使う準備を整えられる。

#### 受け入れ基準

1. When `init` または `update` を実行した, the 導入コマンド shall `.claude/settings.json` と Codex のフックの設定に、一式のフックを登録し、必要な設定ファイルが無ければ作成する。
2. When フックの登録を更新した, the 導入コマンド shall 自分の印がある登録だけを置き換え、利用者のフックとその他の設定値を残す。
3. When 同じ版のフックを再び登録した, the 導入コマンド shall 同じ登録を重複させない。
4. If フックの設定を読み取れず、既存の内容を保って統合できない, the 導入コマンド shall その設定ファイルを変更せず、ファイル名と理由を表示して失敗として終わる。
5. When Codex 向けの登録を案内した, the 導入コマンド shall フックの実行には信頼の承認が必要であることと、未承認の環境では AGENTS.md の指示に従うことを示す。

### Requirement 5: 運用の区画の文章と既存の文書の扱い

**目的**：利用者が、cc-sdd の標準の文書に加えて、両ツールへ同じ趣旨の運用上の指示を渡せる。

#### 受け入れ基準

1. When `init` または `update` を実行した, the 導入コマンド shall CLAUDE.md と AGENTS.md の末尾に書き足す運用の区画の文章を、Claude Code 向けと Codex 向けの共通の配置物として配置する。
2. When 運用の区画の文章を配置した, the 導入コマンド shall session-install・kiro-gate・subagent-delegation が定める案内と、プロジェクト独自の決まりを `.kiro/steering/` の文書から読む案内を、両ツールで同じ趣旨になるよう含める。
3. The 導入コマンド shall 運用の区画の文章に cc-sdd の標準の文書の本文を複製しない。
4. The 導入コマンド shall CLAUDE.md と AGENTS.md を自ら書き換えない。書き出しと運用の区画の書き足しは session-install が行う。
5. When `init` の対象に CLAUDE.md または AGENTS.md がある, the 導入コマンド shall その文書を変更せず、次の cc-sdd の導入で標準の文書に置き換わること、プロジェクト独自の決まりを `.kiro/steering/` へ移すこと、git で追跡中なら追跡を外す操作が利用者に必要であることを表示する。

### Requirement 6: コミット対象の整理

**目的**：利用者が、運用に必要な設定や配置物を共有し、cc-sdd 本体の導入物と手元だけの状態は共有対象から外せる。

#### 受け入れ基準

1. When `init` または `update` を実行した, the 導入コマンド shall Claude Code と Codex 向けの cc-sdd の導入物（CLAUDE.md・AGENTS.md を含む）および手元だけの実行状態を除外する指定を `.gitignore` に加え、ファイルが無ければ作成する。
2. When `.gitignore` の除外設定を更新した, the 導入コマンド shall 自分が管理する部分だけを更新し、それ以外の既存の内容を残す。
3. When 同じ版の除外設定を再び適用した, the 導入コマンド shall 同じ指定を重複させない。
4. The 導入コマンド shall 設定ファイル、共通の配置物、両ツールの共有用のフック設定、利用者の仕様と方針の文書（`.kiro/specs/`・`.kiro/steering/`）を、自分の除外設定によってコミット対象から外さない。
5. When 導入後の共有方法を案内した, the 導入コマンド shall bootstrap の設定・配置物と cc-sdd 本体の導入物を区別し、cc-sdd 本体の取得は session-install の手順で行うことを示す。

### Requirement 7: 運用の取り外し

**目的**：利用者が、広い範囲のファイル削除を伴わずに、登録と運用の区画を外せる。

#### 受け入れ基準

1. When 利用者が `uninstall` を実行した, the 導入コマンド shall Claude Code と Codex のフック設定から自分の印がある登録を取り除き、CLAUDE.md と AGENTS.md に書き足された運用の区画を取り除き、cc-sdd の標準の文書の部分は残す。
2. When `uninstall` を実行した, the 導入コマンド shall 設定ファイル、共通の配置物、`.gitignore`、cc-sdd の導入物、利用者の成果物、および取り外し対象以外の設定と文章を残す。
3. When `uninstall` が完了した, the 導入コマンド shall 取り除いた登録・運用の区画と、削除せずに残る設定ファイル・共通の配置物・除外設定を表示する。
4. If `uninstall` でフックの設定を読み取れない、または運用の区画の目印が壊れている, the 導入コマンド shall 問題のあるファイルを変更せず、理由と修正方法を表示して失敗として終わる。

### Requirement 8: 配置範囲の安全策と結果の通知

**目的**：利用者が、変更の範囲と失敗時の状態を確認でき、対象外の場所への書き込みを避けられる。

#### 受け入れ基準

1. If 実行場所が git リポジトリの最上位ではない, the 導入コマンド shall ファイルを変更せず、実行すべき場所を案内して失敗として終わる。
2. If 変更対象がリポジトリの外になる、または変更先までの経路にシンボリックリンク（別の場所を参照する仕組み）がある, the 導入コマンド shall その場所への変更を拒否し、対象と理由を表示して失敗として終わる。
3. When ファイルを変更または削除した, the 導入コマンド shall この版の配置対象・廃止対象・自分のフック登録・運用の区画（取り除きのとき）・除外設定・初期作成する設定ファイルに変更を限定する。
4. When 操作が成功した, the 導入コマンド shall 作成・更新・削除した対象を日本語で表示し、成功として終わる。
5. If 書き込みの途中で失敗した, the 導入コマンド shall 失敗箇所、既に変更した対象、未処理の対象、再実行する操作を日本語で表示し、失敗として終わる。
6. If 実行環境が Node.js 22 以上という利用条件を満たさない, the 導入コマンド shall ファイルを変更せず、必要な版を日本語で表示して失敗として終わる。
7. When 利用先へ一式を配置した, the 導入コマンド shall 利用先に追加の依存パッケージの導入を要求しない。

### Requirement 9: このリポジトリへの自己適用

**目的**：開発者が、配布するものと同じ一式をこのリポジトリでも利用できる。

#### 受け入れ基準

1. When このリポジトリに一式を適用した, the 導入コマンド shall 他の利用先と同じ操作で、Claude Code と Codex 向けの配置物・フック登録・除外設定を揃える。
2. When このリポジトリへの改訂版の適用が完了した, the 導入コマンド shall 旧配置記録 `.agent-hooks/cc-sdd-bootstrap/installed.json` が残らず、再実行でも作られない状態にする。
3. When 自己適用の直後に同じ版で `update` を再実行した, the 導入コマンド shall ファイルの内容を変えず、変更が無いことを表示する。
4. When このリポジトリへの改訂版の適用が完了した, the 導入コマンド shall このリポジトリ独自の決まりが `.kiro/steering/` の文書にあり、CLAUDE.md と AGENTS.md がコミット対象から外れた状態にする。
