- 対象: 止める指示が、同じ入力に並ぶ他のフックの案内（手順書を先に読む案内、作業ブランチへの切り替えの案内、実物の kiro-gate の終了の停止）と両立し、止めた入力の作業が進まないこと（要件 2.1〜2.4・7.1〜7.3・9.2・9.3、`feasibility.md` の前提 (b)(c)）
- 段階: design

## 実施内容の要点
- `design_01.md` と同じ使い捨てのリポジトリと起動の方法で、次を組み合わせた。止める指示、手順書を先に読む案内（`gate`）、作業ブランチへの切り替えの案内（`branch`）、このリポジトリの実物の `kiro-gate.mjs`（入力・ツールの拒否・終了の停止。手順書の一覧に載らない状態にして、手順書を読むまで他のツールを拒否し、終了を 1 回止める）。登録の順序（止める指示が先／kiro-gate が先）も変えた。
- 手順書は「`OUT.txt` を作り中身を書く」だけの内容にして、作業が進んだかを `OUT.txt` の有無で見た。ツールの使用、ブランチ、リポジトリの変更（`git status`）も見た。

## 実施日・環境と版
- 実施日: 2026-11-26
- 環境: `design_01.md` と同じ（Claude Code 2.1.329、Codex CLI 0.172.0、Node.js v22.16.0）

## 結果
- 止める指示 + 案内 2 種（実物の kiro-gate なし）: Claude Code（haiku・sonnet・auto）、Codex とも、ツールを使わず、`OUT.txt` なし、ブランチは `main` のまま。停止の案内が応答の文章で出た。
- 止める指示 + 実物の kiro-gate: 作業の成果物（`OUT.txt`）は、Claude Code 11 回・Codex 2 回のどれでも作られなかった。停止の案内はすべての応答の文章に出た。
- ただし kiro-gate の終了の停止（手順書を先に読んでから作業を続けるよう求める）が働くと、Claude Code で手順書の読み取り（`Read`、あわせて `Bash`）が起きた。haiku は 3 回中 3 回（ターン数 4。止める指示と kiro-gate の登録順を入れ替えても同じ）、sonnet は 3 回中 1 回（案内 2 種と kiro-gate を全部並べた場合）。Codex は 2 回とも起きなかった。読み取りの後も作業は進まず、リポジトリは変わらなかった。
- haiku の 1 回では、応答の文章が「手順書の読み込みは行っていません」と書いていたが、実際には `Read` が使われていた（応答の文章の自己申告は、ツールの使用と食い違うことがある）。
- 比較用（kiro-gate だけ）: Claude Code・Codex とも、手順書を読み、`OUT.txt` を作った。

## 仕様への反映
- 止める指示だけで、並んだ案内があっても作業（ファイルの作成・編集・状態を変えるコマンド・ブランチの切り替え）は止まる。ツールの拒否による補強は、現時点では入れない（要件 2.4）。作業が進んだ観測が出たら、補強を設計に足す（見直しの条件）。
- 手順書の読み取りは、kiro-gate の終了の停止によって起きる。kiro-gate は変えず、要件 2.1 を「手順書の読み取りは許容する」に直した（利用者の判断。2026-11-26）。
- 確かめられなかったこと: 回数が少ない（Claude Code の停止 + kiro-gate は 6 回、Codex は 2 回）。haiku・sonnet 以外のモデル。実際の cc-sdd の手順書（長い手順書を読んだ後の振る舞い）。実装後の E2E で、実際の配置物と手順書で確かめる。
