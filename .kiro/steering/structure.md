# プロジェクト構成

## 構成の方針

「このリポジトリで動くもの」と「利用先へ配置するもの」を分ける。利用先へ配置するものは、このリポジトリの中でも配置後と同じ相対パスの形で持ち、導入コマンドはそれを写すだけにする（配置物の中身を導入コマンドの中で組み立てない）。

具体的なディレクトリ名は、最初の spec の設計で決めてここに追記する。

## ディレクトリの型（予定）

### 導入コマンド
**目的**: CLI の入口と、配置・更新・設定ファイルの読み書き
**例**: `bin/` の入口と、その下の処理

### 配置物
**目的**: 利用先へ写すファイル（フックのスクリプト、エージェント定義、CLAUDE.md の定型の節）
**例**: 利用先の `scripts/agent/` や `.claude/agents/` に対応する場所

### プラグイン
**目的**: Claude Code のプラグインとしての定義と、会話から導入・更新を行うスキル
**例**: `.claude-plugin/`、スキルの `SKILL.md`

### PoC
**目的**: Claude Code の動作の前提を確かめる、再実行できる検証スクリプトと結果の記録
**例**: 確かめる前提ごとのスクリプト

## 命名

- ファイル: kebab-case（`kiro-gate.mjs` など）
- 関数: camelCase。判定を返す関数は `decide…`、状態を作る関数は名詞で始める

## コードの決まり

- 配置物のスクリプトは、利用先のリポジトリのルートを自分の位置から求める（呼び出し元のカレントに依らない）。
- 配置物は導入コマンドの部品を import しない（利用先には配置物しか無いため）。

---
_ファイルの一覧ではなく型を書く。型に沿った新しいファイルでは更新が要らないようにする_
