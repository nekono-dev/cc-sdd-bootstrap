# プロダクト概要

cc-sdd（Kiro 方式の仕様駆動開発をスキルとして提供する外部ツール）を、各プロジェクトへ 1 つのコマンドで導入・更新する仕組み。skyshare で手作りした運用一式（固定版の自動導入、手順書を読ませるフック、サブエージェントの使い分け）を汎用化し、どのリポジトリにも同じ形で適用できるようにする。指揮役（会話を進めるメインのエージェント）は Claude Code と Codex の両方を対象にする。

大目的は 3 つに絞る（2026-11-22）: ① cc-sdd のスキルをリポジトリに再複製しない、② cc-sdd のスキルが無い初回でも `/kiro-*` を確実に使わせ、使い漏らしをフックで止める、③ サブエージェントのモデルの決まりと別ベンダの利用を機械化する（厳密さのためにコードを増やさない）。

## 中心となる機能

- **導入と更新のコマンド**: `npx` 1 回で、フック・スクリプト・エージェント定義・CLAUDE.md と AGENTS.md の定型の節・`.gitignore` をプロジェクトへ配置する。再実行で更新する。
- **固定版の導入**: cc-sdd の導入物（スキル・雛形）はリポジトリに含めず、設定ファイルの版で入れる。クラウドでは環境の準備スクリプトで起動前に、手元ではセッションの開始・最初の入力のフックで入れる。失敗したら次の入力を止める。
- **手順書の強制（kiro-gate）**: `/kiro-*` で始めた作業は、対応する手順書を読むまで他の操作をさせない。
- **サブエージェントの役割表（subagent-delegation）**: 役割（設計・実装・レビューなど）ごとにベンダ・モデル・推論量・権限を設定ファイルで決め、指揮役と同じモデルや未指定での起動をフックで拒否する。子には別ベンダの CLI（`codex exec`・`claude -p`）を積極的に使う。

## 想定する使い方

- 新しいリポジトリで cc-sdd の運用を始める（クラウドセッションでも、環境の準備直後から `/kiro-*` が使える）。
- 既存の手作りの運用（skyshare）を置き換え、版の更新を 1 か所で行う。
- Claude Code のトークンを使い切ったときに、Codex を指揮役にして同じ運用を続ける。

## 価値

- cc-sdd 本体を配らない・コミットしない。ライセンス（cc-sdd は MIT）の異なる成果物を各リポジトリに持ち込まない。
- 決まりを文章ではなくフックで強制する。エージェントが指示を読み落としても運用が崩れない。
- コストの規律: 重い作業はより安いモデルに任せ、指揮役と同じモデルで二重に払う状態を作らない。
