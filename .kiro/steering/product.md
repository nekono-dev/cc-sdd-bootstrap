# プロダクト概要

cc-sdd（Kiro 方式の仕様駆動開発を Claude Code のスキルとして提供する外部ツール）を、各プロジェクトへ 1 つのコマンドで導入・更新する仕組み。skyshare で手作りした運用一式（固定版の自動導入、手順書を読ませるフック、サブエージェントの使い分け）を汎用化し、どのリポジトリにも同じ形で適用できるようにする。

## 中心となる機能

- **導入と更新のコマンド**: `npx` 1 回で、フック・スクリプト・エージェント定義・CLAUDE.md の定型の節・`.gitignore` をプロジェクトへ配置する。再実行で更新する。
- **セッション開始時の固定版導入**: cc-sdd の導入物（スキル・雛形）はリポジトリに含めず、セッション開始のたびに設定ファイルの版で入れ直す。失敗したら次の入力を止める。
- **手順書の強制（kiro-gate）**: `/kiro-*` で始めた作業は、対応する手順書を読むまで他の操作をさせない。roadmap に載せた新しい spec の brief が欠けたまま終わらせない。
- **サブエージェントのモデル固定**: サブエージェントを使う役割（設計・実装・レビューなど）ごとにモデルを設定ファイルで固定し、指揮役（会話を進めるメインのエージェント）と同じモデルでの起動をフックで拒否する。
- **Codex への委任（選択制）**: 導入時に Codex MCP サーバーを使うかを選べる。

## 想定する使い方

- 新しいリポジトリで cc-sdd の運用を始める（クラウドセッションでも、環境の準備直後から `/kiro-*` が使える）。
- 既存の手作りの運用（skyshare）を置き換え、版の更新を 1 か所で行う。
- Claude Code のプラグインのスキルとして、会話から導入・更新を頼む。

## 価値

- cc-sdd 本体を配らない・コミットしない。ライセンス（cc-sdd は MIT）の異なる成果物を各リポジトリに持ち込まない。
- 決まりを文章ではなくフックで強制する。エージェントが指示を読み落としても運用が崩れない。
- コストの規律: 重い作業はより安いモデルに任せ、指揮役と同じモデルで二重に払う状態を作らない。
