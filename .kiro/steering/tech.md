# 技術スタック

## アーキテクチャ

2 つの面を持つ。

- **導入コマンド**（このリポジトリで動く）: 利用先のリポジトリへファイルを配置・更新する CLI。
- **配置物**（利用先で動く）: Claude Code のフックから呼ばれるスクリプト群と設定。導入後は導入コマンドなしで動き、利用先のリポジトリだけで完結する（クラウドセッションで、プラグインの導入を待たずに動かすため）。

同じリポジトリを Claude Code のプラグインとしても配り、会話から導入コマンドを使えるようにする。

## 中心となる技術

- **言語**: JavaScript（ESM、`.mjs`）
- **実行環境**: Node.js 22 以上
- **外部パッケージ**: 使わない（Node の標準モジュールだけ）。`npx` での取得を速くし、利用先に依存を持ち込まないため。

## 開発の決まり

### コード
- コード内のコメントと利用者向けの出力は日本語で書く。
- フックは「判定できないときは通す」か「止める」かを部品ごとに決めて明記する。導入の失敗は止める側、手順書の強制は判定できなければ通す側。

### テスト
- 単体テストは `node --test`。
- Claude Code の動作に依存する前提（フックの入出力、許可の判定の優先順位、サブエージェントのモデルの決まり方など）は、PoC（実際の `claude -p` を一時ディレクトリで動かす検証）で確かめ、再実行できるスクリプトとして残す。cc-sdd や Claude Code の版を上げたときに同じ PoC で互換を確かめる。

## 開発環境

### 必要なもの
- Node.js 22 以上、git
- PoC の実行には Claude Code（`claude`）とその認証

### よく使うコマンド
```bash
npm test                                      # node --test "test/**/*.test.mjs"
node bin/cc-sdd-bootstrap.mjs init            # このリポジトリへの適用
node bin/cc-sdd-bootstrap.mjs update          # 適用内容の確認・更新
node bin/cc-sdd-bootstrap.mjs uninstall       # 適用内容の取り除き
poc/<名前>/run.sh                            # 個別の前提確認
```

現時点では、設定ファイルに保存した cc-sdd の版と言語は導入処理に反映されない。配置物の導入スクリプトは版 3.1.0・言語 ja を固定している。Codex の利用設定と役割ごとのモデルも今は保存だけで、後続の仕様で反映する。

## 主要な技術判断

- **配布は `npx github:nekono-dev/cc-sdd-bootstrap`**: 公開リポジトリなので認証が要らない。GitHub Packages（認証が要る）は使わない。
- **cc-sdd の導入物はリポジトリに含めない**: 利用先でも `.gitignore` の対象にする。現時点ではセッション開始時に版 3.1.0・言語 ja で入れ直す。設定ファイルの版と言語を読む動きは後続の仕様で対応する。
- **CLAUDE.md は管理区画だけを書き換える**: 目印の行で囲んだ範囲の外は、プロジェクトの文書として触らない。
- **cc-sdd の標準の決まりの文書は CLAUDE.md に書かせない**: cc-sdd が CLAUDE.md 向けに生成する文書は、導入物として別ファイル（`.kiro/settings/cc-sdd-guide.md`）へ出力し、CLAUDE.md の管理区画から `@` の取り込みで読ませる。導入物なのでコミットせず、版に合わせて毎回作り直す。cc-sdd の版の更新で CLAUDE.md の差分が出ないようにするため（2026-11-18、取り込みが効くこと・ファイルが無くても壊れないことを PoC で確認）。
- **このリポジトリ自身にも適用する**: 導入コマンドができたら、このリポジトリにも同じ方法で導入し、作るものを自分で使って確かめる。
