# cc-sdd-bootstrap

[cc-sdd](https://github.com/gotalab/cc-sdd)（Kiro 方式の仕様駆動開発を Claude Code のスキルとして提供するツール）の運用一式を、Git リポジトリへ導入・更新・削除するコマンドです。

## 必要なもの

- Node.js 22 以上
- git

## 使い方

リポジトリの最上位ディレクトリで実行します。

```sh
npx github:nekono-dev/cc-sdd-bootstrap init
npx github:nekono-dev/cc-sdd-bootstrap update
npx github:nekono-dev/cc-sdd-bootstrap uninstall
```

- `init`: cc-sdd の運用一式を導入します。
- `update`: 設定を保ち、同梱ファイルやフック登録を更新します。
- `uninstall`: このコマンドが管理するものを取り除きます。

入手するコマンドの版を固定するには、`#<タグ>` を `github:nekono-dev/cc-sdd-bootstrap` の末尾に空白なしで付けます。たとえば `npx github:nekono-dev/cc-sdd-bootstrap#v1.2.3 init` のようにします。

### オプション

```text
--cc-sdd-version <値>   cc-sdd の版
--lang <値>             cc-sdd の言語（例: ja、en、pt-BR）
--codex yes|no           Codex を使うか
--model <役割>=<モデル>  役割ごとのモデル（繰り返し指定可能）
--keep-templates yes|no  設定の雛形を保持するか
--force                 内容が変更された共通ファイルも置き換える
--help                  使い方を表示する
```

設定オプション（`--cc-sdd-version`、`--lang`、`--codex`、`--model`、`--keep-templates`）は `init` と `update` でだけ使えます。`--force` と `--help` は3つの操作で使えます。

設定は `.cc-sdd-bootstrap.json` に保存されます。初めて `init` を端末から実行するときは、引数で指定していない設定項目を尋ねます。役割ごとのモデル一覧は空のままでも質問しません。入力と出力が端末につながっていない場合は、未指定の項目を既定値で補います。`update` は既存の設定に引数で指定した値を重ねて使い、質問はしません。`uninstall` も質問しません。

保存した cc-sdd の版と言語は、セッション開始のたびに cc-sdd の導入物を揃えるときに使われます。導入物がすでに揃っていれば入れ直しを省きます。Codex の利用設定と役割ごとのモデルは現時点では保存だけで、後続の機能で反映する予定です。

設定 `ccSdd.keepTemplates` は、設定の雛形（`.kiro/settings/templates/`）を毎回の入れ直しで上書きせず保持し、コミットできるようにする選択です。既定では保持しません。雛形は cc-sdd の成果物で MIT ライセンスのため、コミットする場合はそのライセンスに従ってください。保持すると cc-sdd の版を上げても雛形は入れ替わりません。入れ替えるには `.kiro/settings/templates/` を削除して新しいセッションを開きます。

## 配置されるもの

- `.cc-sdd-bootstrap.json`: cc-sdd の版・言語、Codex の利用、役割ごとのモデル設定。
- `.agent-hooks/cc-sdd-bootstrap/`: フックから使うスクリプト。`installed.json` は配置内容と版の記録です。`freshness.mjs` と `freshness-rules.mjs` は、セッション開始時に導入の鮮度を確かめるスクリプトです。
- `.agent-hooks/cc-sdd-bootstrap/install-record.json`: 導入の記録。導入・更新のたびに作られ、配布元の版と配置物の指紋が書かれます。詳しくは下の「導入の記録と鮮度の案内」を見てください。
- `.claude/settings.json`: セッション開始時と入力時に動くフックの登録。
- `.gitignore` と `CLAUDE.md`: cc-sdd の導入物や標準の決まりを案内する、コマンド管理の区画。

設定ファイル、配置されたスクリプトと記録、フック設定、`.gitignore` と `CLAUDE.md` の変更をまとめてコミットしてください。cc-sdd が生成する `.claude/skills/kiro-*/` や `.kiro/settings/` は `.gitignore` の対象で、コミットしません。

## 導入の記録と鮮度の案内

導入・更新のたびに、`.agent-hooks/cc-sdd-bootstrap/install-record.json` が作られ、更新されます。この記録には次の 2 つが書かれます。

- 配布元の版: 取り込んだ配布元の変更の識別番号（コミット）です。40 桁の英数字で、取り出せなかったときは、その旨が記録されます。
- 指紋: 配置したファイルごとに、内容から計算した短い識別値です。内容が 1 文字でも変わると値も変わります。

記録は配置物と一緒にコミットしてください。利用者が編集するものではありません。

セッションを開始するたびに、記録と配置物を照合します。記録に載っているファイルが無い（欠けている）場合や、内容が記録と違う場合は、その旨を案内します。通信できるときは、配布元の最新の版とも比べます。最新と違えば、その旨を案内します。ずれがあるときは、更新コマンドも案内します。

- 案内は入力や作業を止めません。自動で更新することもありません。
- 通信できないときや記録が読めないときも、止めずに作業を続けられます。
- 内容が記録と違っても、利用者が編集したとは断定しません。更新が途中で止まったか、版が混ざっている可能性として案内します。

案内に出る更新コマンドは次のとおりです。ブランチやタグを指定して導入した場合は、その指定も付きます。

```sh
npx -y github:nekono-dev/cc-sdd-bootstrap update
```

この仕組みが入る前の古い導入には、検知の仕組みがありません。そのため、初回だけは手で上の更新コマンドを実行してください。記録が無いときも、更新を案内します。

## ファイルの変更と削除

共通ファイルが配置後に書き換えられていると、`update` と `uninstall` は何も変更せず中止します。内容を確認したうえで `--force` を付けると、共通ファイルを上書きまたは削除できます。`init` と `update` は、プロジェクト固有の配置ファイルが既にあれば保持します。`uninstall` は、配置したときから変わっていないプロジェクト固有ファイルを削除し、変更されていれば残します。管理区画の外にある利用者の記述やフック設定も保持します。

`uninstall` はこのコマンドが配置したファイルと登録・管理区画を取り除きます。設定ファイルが壊れていても、その値を使わず警告を表示して取り除きを続けます。cc-sdd 自体が導入した出力（`.claude/skills/kiro-*/` など）と `.kiro/` の内容は削除しません。

`.claude/settings.json` は書き込み時に空白2つの字下げで整形されます。同じリポジトリでコマンドを同時に実行することはサポートしていません。

## 終了コード

- `0`: 成功、変更なし、またはヘルプ表示
- `1`: 実行時の失敗や前提条件の不足
- `2`: 操作名やオプションなど、使い方の誤り
